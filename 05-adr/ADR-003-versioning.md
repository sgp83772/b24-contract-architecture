# ADR-003: Версионирование файлов договоров через HL-блок + S3

**Статус:** Принято
**Дата:** 2026-11-02

## Контекст
По каждому договору нужно хранить несколько версий подписанных документов (PDF, сканы, приложения). Средний договор — 5–7 версий, крупный — до 30. Файлы весят 1–10 МБ. Всего в системе ~10 000 договоров × 6 версий ≈ 60 000 файлов, ~300 ГБ.

## Проблема
Где хранить версии файлов, чтобы не раздувать MySQL Bitrix24 и сохранить историю версий с авторами?

## Рассмотренные варианты

### Вариант 1. Поле «Файл» в карточке договора (штатное)
- **Плюсы:** просто, всё в Bitrix24.
- **Минусы:** нет истории версий; при перезаписи старая версия теряется; файлы в MySQL-файлах (b_file), раздувают БД и бэкапы.

### Вариант 2. HL-блок + файлы в Bitrix24
- **Плюсы:** история версий есть.
- **Минусы:** все файлы всё равно в Bitrix24 → те же 300 ГБ в бэкапах MySQL.

### Вариант 3. HL-блок + S3
- **Плюсы:** история версий в HL-блоке; файлы в объектном хранилище (дешевле, не в бэкапах БД); штатное поле «Файл» в HL-блоке поддерживает S3 в коробочной версии.
- **Минусы:** нужен настроенный S3 (MinIO или облако).

## Решение
Выбран **HL-блок «Версия документа»** + файлы в S3.

## Структура HL-блока
| Поле | Тип | Назначение |
|---|---|---|
| ID | int | PK |
| CONTRACT_ID | int | ссылка на договор |
| VERSION | int | номер версии |
| FILE | file | файл (хранится в S3) |
| AUTHOR_ID | int | кто загрузил |
| CREATED_AT | datetime | когда |
| COMMENT | text | комментарий к версии |

## Последствия
**Положительные:**
- История версий полная, с авторами.
- Бэкапы MySQL не раздуваются.
- Стоимость хранения ниже.

**Отрицательные:**
- Нужен S3 (MinIO в on-prem).
- Восстановление файла требует доступа к S3 отдельно от БД.
